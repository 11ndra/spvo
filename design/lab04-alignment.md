# ЛР №4 — таблица согласованности с Главой 5

Статус: `DESIGN VERIFIED` для `idps-lab04-bundle-v0.2`.

Цель эксперимента: удержать неизменными источник данных, точку наблюдения и набор событий, меняя только основание принятия решения. В качестве источника используется один JSONL-журнал учебного HTTP-сервиса. Лаборатория не обучает синтаксису правил Suricata.

| Понятие из Главы 5 | Действие студента | Наблюдаемый артефакт | Допустимый вывод | Что артефакт не доказывает |
|---|---|---|---|---|
| Сигнатурное обнаружение | Запускает готовый сценарий с запросом, содержащим `LAB4-KNOWN-BAD`, затем применяет detector `signature` | Строка события с известным маркером + результат `SIGNATURE MATCH` | Наблюдение совпало с заранее определённым условием | Что запрос был вредоносным в реальной системе или привёл к компрометации |
| Анализ состояния/семантики | В сценарии `DATA` для учебной сессии приходит до `START`; студент применяет detector `protocol` | Упорядоченные события `/session/data`, `/session/start`, `/session/data`, `/session/end` + `STATE VIOLATION` | Последовательность нарушила заданную state-machine учебного протокола | Что HTTP как стандарт нарушен или что причиной является атака |
| Фиксированное условие над серией событий | Сценарий создаёт короткий всплеск `/catalog`; студент применяет детектор `threshold` | Временные метки серии запросов + срабатывание фиксированного условия `>=5 запросов за 2 с` | Выполнено заранее заданное условие над несколькими событиями | Что активность отклоняется от реальной нормы среды |
| Аномальное обнаружение | Сценарий сначала создаёт базовый профиль `/catalog`, затем всплеск; студент применяет детектор `anomaly` | Медианные интервалы базового профиля и всплеска, их отношение + `ANOMALY` | Всплеск существенно отличается от базовой модели данного контролируемого прогона | Что отклонение вредоносно или что модель репрезентативна для рабочей среды |
| Сопоставление оснований | Запускает `--method all` и сопоставляет результаты | Один исходный `lab4-events.jsonl` и четыре независимых результата анализа | Один набор событий можно проверять по нескольким основаниям | Что эти четыре основания образуют универсальную классификацию методов обнаружения |

## Контролируемые переменные

Не меняются:

- две VM и адресация курса;
- один учебный web-сервис `10.13.37.20:8080`;
- один файл событий `/var/tmp/idps-lab/lab4-events.jsonl`;
- один сценарий генерации событий;
- один набор временных меток и атрибутов событий.

Меняется только основание принятия решения при анализе файла событий.

## Граница модели

`START → DATA → END` — синтетический прикладной протокол поверх HTTP-маршрутов. Он специально прост, чтобы студент видел state transition без необходимости изучать сложный реальный протокол. Этот пример не утверждает, что HTTP требует такой последовательности.

Поле `phase`, передаваемое заголовком `X-Lab-Phase`, является меткой контролируемого эксперимента. Оно используется только для разделения базового профиля и всплеска при проверке аномального детектора и не является признаком вредоносности.
