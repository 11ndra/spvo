# Chapter 1 visual/UI audit — v2.29-rc4

Цель прохода: сделать Главу 1 эталонной для дальнейшего visual/UI refactor, не меняя её дидактическую последовательность и не заменяя техническую точность декоративностью.

## Решения по визуальным элементам

| Элемент Главы 1 | Решение | Причина |
|---|---|---|
| Вводный lead и learning outcomes | оставить существующую базовую оболочку | это общестраничные компоненты, а не техническая схема; их миграция не даёт учебной ценности |
| Схема 1 — базовая политика доступа | Mermaid, оболочка `idps-figure` | схема небольшая и меняется вместе с текстом; удалён пунктир со значением «запрещено», чтобы пунктир не конфликтовал с семантикой копии данных |
| Список allow/deny | HTML/CSS `idps-policy-*` | policy decision лучше читается как текстовый responsive-компонент, чем как рисунок |
| «РАЗРЕШЕНО ≠ БЕЗОПАСНО» | HTML/CSS `idps-equation` | это концептуальная аксиома, а не сетевой граф |
| Firewall vs IDS/IPS | HTML/CSS + progressive switcher | статические карточки дают обзор; переключатель показывает вопрос → основание → результат → границу вывода |
| Схема 2 — один опубликованный путь, два запроса | Mermaid, оболочка `idps-figure` | сохранён небольшой flowchart; пунктир удалён, потому что он не означал копию данных |
| Два HTTP-примера | HTML/CSS `idps-code-card` | синтаксис должен оставаться настоящим текстом/кодом, а не пикселями |
| Базовая модель IDS | HTML/CSS `idps-process` | четыре шага линейны; цвета точечно отделяют доступные данные, анализ и результат, не заменяя подписи |
| Событие vs оповещение | HTML/CSS `idps-card` | карточки достаточны; событие оставлено нейтральным, alert помечен как result |
| Схема 3 — пассивный NIDS | Mermaid | пунктир здесь имеет канонический смысл: копия наблюдаемого трафика |
| Пример alert | HTML/CSS `idps-result-card` | результат обнаружения выделяется как отдельный артефакт |
| Подтверждено / не подтверждено | HTML/CSS `idps-evidence-*` | это граница доказательной силы, а не схема топологии |
| «ОПОВЕЩЕНИЕ ≠ КОМПРОМЕТАЦИЯ» | HTML/CSS `idps-equation` | ключевая аксиома |
| IDS vs IPS | HTML/CSS `idps-contrast` | объясняет функциональное расширение «обнаружить → обнаружить + воздействовать» без тезиса IDS=passive / IPS=inline |
| Цена ошибки alert-only vs prevention | HTML/CSS cards | сравнение последствий, без преждевременного FP/FN taxonomy |
| Ненужный SSH-путь | HTML/CSS `idps-decision` | одиночное policy decision |
| NGFW как платформа функций | HTML/CSS `idps-stack` | продукт и функции показываются без новой сетевой топологии |
| WAF vs IDS/IPS | HTML/CSS cards | область применения сравнивается текстово, без ложной OSI-дихотомии |
| Схема 4 — от разрешённого трафика к alert | Mermaid | сохраняет путь данных, точку наблюдения, копию и result в одной небольшой схеме |
| Финальная граница доказательств | HTML/CSS `idps-evidence-*` | закрепляет «что можно / чего нельзя заключать» |
| Четыре идеи главы | HTML/CSS `idps-summary-*` | итоговая карта понятий |
| Самопроверка | существующий quiz JS/CSS | уже функциональна; не относится к новому визуальному слою |

## Семантические проверки

После refactor в Главе 1 выполняются следующие правила:

- пунктир в Mermaid используется только для **копии наблюдаемых данных**;
- `allowed ≠ safe`;
- межсетевой экран не сводится к L3/L4;
- IDS/IPS не определяется через physical placement;
- `event ≠ alert`;
- `alert ≠ compromise`;
- IDS/IPS как функция не смешивается с физическим продуктом;
- WAF не объявляется универсальным эквивалентом IDS/IPS;
- без JavaScript оба содержательных состояния switcher остаются доступны как обычный текст;
- с JavaScript controls становятся доступны и поддерживают клавиатуру.
