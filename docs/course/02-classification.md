# Глава 2. Какие виды IDS/IPS существуют и что они могут наблюдать

<div class="chapter-lead">
<p>В первой главе сетевой сенсор получил копию HTTP-трафика и сформировал alert. Но вторжение не обязательно оставляет только сетевые следы.</p>
<p>Запуск процесса, изменение файла, неизвестная точка Wi‑Fi и необычный сетевой обмен — разные явления. <strong>Один источник данных не обязан одинаково хорошо показывать их все.</strong></p>
</div>

<strong>После изучения главы студент должен уметь:</strong>
<p>объяснить различия между network-based, host-based и wireless IDPS; объяснить место Network Behavior Analysis в классической классификации; определить, какие сведения потенциально доступны каждому типу; не путать источник данных с методом обнаружения.</p>

## 1. Почему одной IDS недостаточно

Рассмотрим простой эпизод:

```text
1. Сервер получил сетевой запрос
2. На сервере запустился новый процесс
3. Процесс изменил файл
4. Сервер установил исходящее соединение
```

В сети могут быть видны адреса, порты, соединения, протоколы, объёмы и время передачи. На самом хосте возникают другие сведения: процессы, пользователи, файлы, локальные события ОС.

Отсюда базовая идея:

```text
Разные действия оставляют разные следы.
Разные IDPS получают разные виды данных.
```

---

## 2. Классическая классификация IDPS

В NIST SP 800-94 используется четыре основных типа IDPS:

```text
Network-Based
Wireless
Network Behavior Analysis (NBA)
Host-Based
```

Эту классификацию важно знать, потому что она встречается в учебной литературе и документации.

Но она не идеально симметрична. Network, Host и Wireless во многом отвечают на вопрос **где и из какой среды наблюдается активность**, а NBA сильнее характеризует тип сетевой телеметрии и характер анализа.

Поэтому дальше мы будем различать два вопроса:

```text
ОТКУДА получены данные?
        ≠
КАК эти данные анализируются?
```

---

## 3. Network-Based IDS/IPS — NIDS/NIPS

**NIDS/NIPS** анализирует доступную ему сетевую активность.

```text
Host A ───────────────► Host B
              │
              │ доступная копия / поток
              ▼
             NIDS
```

В зависимости от observation point, конфигурации и возможностей системы она может получать и анализировать, например:

```text
IP-адреса
TCP/UDP-порты
TCP flags
ICMP
DNS
HTTP
SMB
TLS metadata
характеристики flows
```

Ключевое слово — **доступную**.

NIDS не обязательно видит весь трафик инфраструктуры. Если коммуникация не достигает её observation point или нужные данные недоступны, соответствующий сетевой след может отсутствовать в её telemetry.

### Что NIDS не знает автоматически

Если NIDS увидела:

```text
10.10.1.15 → 10.10.2.20:445
```

из одного сетевого наблюдения не следует, какой локальный процесс на `10.10.1.15` создал соединение.

Для ответа на такой вопрос нужен другой источник данных.

---

## 4. Host-Based IDS/IPS — HIDS/HIPS

**HIDS/HIPS** работает с событиями и характеристиками конкретного вычислительного узла.

```text
┌───────────────────────────────┐
│            SERVER             │
│                               │
│ process                       │
│ file                          │
│ users                         │
│ audit events                  │
│ local connections             │
│          │                    │
│          ▼                    │
│      HIDS agent               │
└───────────────────────────────┘
```

HIDS **может** получать сведения о процессах, системных событиях, файлах, пользователях, изменениях конфигурации, локальной сетевой активности и журналах ОС/приложений.

Но наличие агента не означает автоматической доступности любой возможной telemetry. Это зависит от продукта, ОС, настроенных источников аудита, прав и конфигурации.

### Один эпизод глазами NIDS и HIDS

Пусть сервер устанавливает исходящее соединение:

```text
Web Server → 203.0.113.50:443
```

NIDS потенциально покажет сетевой факт: кто, куда, когда и по какому протоколу взаимодействовал.

HIDS на Web Server потенциально сможет дополнить контекст:

```text
process = X
PID = 4217
user = www-data
parent = nginx
```

Получаем два разных взгляда:

```text
NETWORK VIEW → что произошло в коммуникации
HOST VIEW    → что происходило внутри конкретного узла
```

Один источник не является автоматически «лучше» другого.

## 5. Wireless IDS/IPS — WIDS/WIPS

Беспроводная сеть добавляет отдельную среду наблюдения — радиоэфир и протоколы 802.11.

**WIDS/WIPS** анализирует wireless activity и может использоваться, например, для выявления неизвестных access points, неожиданных wireless clients, подозрительных management frames и других событий беспроводной среды.

```text
      Laptop
        )))
         )))
      Access Point

           )))
       WIDS Sensor
```

Обычный NIDS, подключённый к проводному сегменту после access point, может видеть часть IP-трафика клиента, но не обязан располагать тем же представлением радиообмена 802.11, которое доступно wireless sensor.

Wireless monitoring имеет собственные ограничения: радиопокрытие, каналы, способ сканирования и возможности конкретного оборудования.

---

## 6. Network Behavior Analysis — NBA

**Network Behavior Analysis (NBA)** анализирует сетевой трафик или статистику сетевой активности с целью обнаружения необычных flow patterns и изменений сетевого поведения.

Например:

```text
обычно:
Server A → 20 внешних flows в час

сейчас:
Server A → 12 000 flows за несколько минут
```

Или:

```text
обычно:
Workstation → Servers

необычно:
Workstation → сотни Workstations
```

Здесь интерес представляет не обязательно конкретная строка известного exploit, а изменение характера сетевой активности.

### Почему NBA выбивается из классификации

NIDS и NBA оба используют сетевые данные. Поэтому граница между ними не абсолютна.

Условно:

```text
NIDS → часто более глубокий packet/protocol inspection
NBA  → акцент на flows, статистике и изменениях поведения
```

Но современные продукты могут совмещать обе группы возможностей.

Термин NBA полезно знать как исторически важную категорию. Современные обозначения NTA и NDR встречаются часто, но их границы зависят от конкретного продукта и источника.

## 7. А Application-Based IDS — это пятый тип?

В литературе можно встретить **Application-Based IDPS** — систему, ориентированную на конкретный application service, например web server или DBMS.

В классической модели NIST application-based IDPS рассматривается как разновидность host-based IDPS.

Поэтому в базовой классификации курса мы не создаём отдельную пятую равноправную категорию, но запоминаем важную идею:

> Источник security-relevant data может находиться очень близко к самому приложению.

## 8. Тип IDS и метод обнаружения — не одно и то же

Это одна из ключевых границ курса.

**Тип / источник наблюдения** отвечает на вопрос:

> Откуда система получает данные о происходящей активности?

**Метод обнаружения** отвечает:

> Как система принимает решение на основании этих данных?

Поэтому неправильно строить один ряд:

```text
Network
Host
Wireless
Behavioral
```

Корректнее разделить:

```text
ГДЕ / ИЗ ЧЕГО НАБЛЮДАЕМ
Network / Host / Wireless / ...

КАК АНАЛИЗИРУЕМ
signature / protocol-state / behavioral / anomaly / ...
```

Методы detection подробно появятся в Главе 5.

## 9. Один эпизод — разные взгляды

!!! note "Учебная модель / синтетический сценарий"
    На Web Server выполняется неизвестный процесс, который изменяет файл и устанавливает множество исходящих соединений.

```text
Web Server
├─ process X
├─ modifies file
└─ many outbound connections
```

**Network-based IDPS** может показать доступные соединения, адреса, порты, протокольные признаки и объёмы трафика.

**Host-based IDPS** может показать process X, пользователя, изменение файла и локальный network socket — если такая telemetry действительно настроена.

**NBA/NTA-подобный анализ** может выделить резкое изменение числа/характера flows.

**Wireless IDPS** может вообще не дать полезного свидетельства по этому эпизоду, если интересующая активность не относится к wireless domain.

Это нормально: средство защиты не становится «плохим» только потому, что событие находится вне области его наблюдения.

## 10. Почему несколько источников могут дополнять друг друга

Например:

```text
NIDS:
видит подозрительное соединение

        +

HIDS:
показывает процесс,
создавший соединение

        =

более сильный контекст
```

Но больше telemetry — не автоматически лучше. Больше источников означает дополнительные данные, хранение, настройку, вычисления и сопровождение.

Цель архитектуры мониторинга — не собрать всё подряд, а обеспечить **достаточную наблюдаемость для нужных задач безопасности**.

## 11. Как выбирать источник наблюдения

Вместо вопроса «какая IDS лучше?» сначала задайте вопрос:

> **Какое явление требуется наблюдать и где существует нужный след?**

Примеры:

```text
изменение критичного файла
→ host event / FIM
→ HIDS
```

```text
внутреннее сетевое сканирование
→ множество сетевых взаимодействий
→ network telemetry
→ NIDS / flow analysis
```

```text
rogue access point
→ radio / 802.11 activity
→ WIDS
```

Выбор продукта появляется после понимания задачи и доступных источников данных.

## 12. Что нужно запомнить

```text
NETWORK VIEW ≠ HOST VIEW
WIRELESS VISIBILITY ≠ WIRED VISIBILITY
DATA SOURCE ≠ DETECTION METHOD
ONE SENSOR ≠ COMPLETE VISIBILITY
```

## Источники и статус классификации

- NIST SP 800-94 — источник классической четырёхчастной taxonomy: Network-Based, Wireless, NBA, Host-Based.
- В курсе эта taxonomy рассматривается как **историческая фундаментальная классификация**. Мы не выдаём NBA/NTA/NDR за современный универсальный набор взаимно исключающих категорий.
- Application-Based IDPS рассматривается в NIST как разновидность host-based monitoring для конкретного application service.
