## Язык и терминология курса

Основной язык курса — **русский**. Английский термин приводится при первом вводе, если он нужен для чтения стандарта, RFC или документации продукта; далее используется русский эквивалент или устоявшаяся аббревиатура.

Пример: **система обнаружения вторжений (Intrusion Detection System, IDS)** → далее `IDS` или «система обнаружения вторжений». Названия параметров и полей конфигурации (`flow`, `http.uri`, `sid`) не переводятся, потому что это синтаксис конкретного продукта.

# Глоссарий

| Термин | Значение в курсе |
|---|---|
| IDS | Система обнаружения вторжений; автоматизирует наблюдение и анализ на признаки возможных инцидентов. |
| IPS | Система предотвращения вторжений; сочетает обнаружение с возможностью инициировать предотвращающее воздействие. |
| IDPS | Обобщённое обозначение IDS и IPS, когда различие между обнаружением и предотвращением не является предметом конкретного утверждения. |
| NIDS/NIPS | Сетевая IDS/IPS: получает и анализирует сетевые данные в доступной ей точке наблюдения. |
| HIDS/HIPS | Хостовая IDS/IPS: получает данные о событиях и характеристиках конкретного узла. |
| WIDS/WIPS | Беспроводная IDS/IPS: наблюдает беспроводную среду и протоколы соответствующего класса. |
| NBA | Анализ сетевого поведения (Network Behavior Analysis) — исторический термин NIST для анализа необычных сетевых потоков и статистики. |
| Оповещение (alert) | Выделенный результат обнаружения, означающий выполнение заданного условия детектора; само по себе не подтверждает компрометацию. |
| Сигнатура | Формализованный наблюдаемый признак или комбинация условий, используемая детектором. |
| Правило обнаружения | Машинно-исполняемая конструкция, формализующая область применения, проверяемые условия, контекст и результат/действие конкретного движка. |
| `sid` | Идентификатор сигнатуры Suricata; используется для однозначного различения правил и их результатов. |
| `rev` | Номер редакции сигнатуры Suricata. |
| `msg` | Человекочитаемое описание сигнатуры/оповещения Suricata; не является условием совпадения. |
| `flow` | Ключевое слово Suricata для ограничения проверки контекстом потока, например направлением или состоянием соединения. |
| Точка наблюдения | Конкретное место, где система получает интересующие данные: например сетевой интерфейс, сегмент или граница между сетями. |
| Пассивное подключение | Система получает копию данных и не является обязательной транзитной точкой основного сетевого потока. |
| Inline-подключение | Основной сетевой поток проходит через систему. Не означает автоматически, что блокирование включено. |
| SPAN | Зеркалирование выбранного трафика средствами коммутатора на порт, используемый для мониторинга. |
| TAP | Сетевой ответвитель, предоставляющий отдельную копию трафика наблюдаемой линии. |
| Телеметрия | Данные о наблюдаемой активности системы или сети, доступные выбранному источнику. |
| Сетевой поток (flow) | Логически связанная последовательность сетевых пакетов/сообщений между участниками взаимодействия в рамках выбранной модели. |
| EVE JSON | Структурированный формат событий Suricata. |
| HOME_NET | Переменная Suricata, описывающая защищаемые сети или адреса для правил, которые её используют. |
| TP / FP / TN / FN | Категории результатов классификации относительно заранее определённых единицы оценки и эталонного истинного состояния (ground truth). |
| Ground truth | Независимое основание считать конкретную единицу оценки положительной или отрицательной; не должно определяться тем же alert, который оценивается. |
| Recall / TPR | Доля положительных единиц оценки, которые детектор выделил: `TP / (TP + FN)`. |
| Precision | Доля положительных решений детектора, которые подтверждаются ground truth: `TP / (TP + FP)`. |
| False Positive Rate (FPR) | Доля отрицательных единиц оценки, ошибочно выделенных детектором: `FP / (FP + TN)`. |
| Accuracy | Общая доля правильных решений на заданной выборке: `(TP + TN) / (TP + FP + TN + FN)`; может вводить в заблуждение при сильном дисбалансе классов. |
| Evaluation Contract | Зафиксированные условия оценки: цель, единица оценки, ground truth, сопоставление alert с объектом, выборка/окно, среда и версия, критерии приёмки и границы применимости. |
| Наблюдаемый признак | Признак активности, который реально доступен выбранному источнику данных. |
| Sticky buffer | Именованная область данных Suricata, к которой применяются последующие условия правила. |
| Идентификация протокола (protocol identification) | Определение прикладного протокола по доступным признакам потока и состоянию; не сводится автоматически к номеру порта. |
| Reassembly | Восстановление логического потока/сообщения из сетевых фрагментов или сегментов, необходимое до части stateful и прикладного анализа. |
| Parser | Компонент, который интерпретирует доступный поток как конкретный протокол и выделяет его структуру, транзакции и поля. |
| Транзакция протокола | Структурированная единица обмена, выделенная parser, например DNS query/response или HTTP request/response. |
| Normalization | Приведение доступного протокольного представления к более канонической форме перед анализом; её семантика является частью условий обнаружения. |
| QUIC | Защищённый transport поверх UDP, предоставляющий потоки, multiplexing и управление соединением; используется, в частности, HTTP/3. |
| ECH | Encrypted Client Hello — механизм TLS, защищающий внутренний ClientHello и чувствительные поля, включая SNI в поддерживаемых сценариях. |
| DoT / DoH / DoQ | Передача DNS соответственно поверх TLS, HTTPS и QUIC; меняет сетевое представление DNS для внешнего сенсора. |
| Регрессионная проверка | Повторяемая проверка ранее определённых тестовых случаев после изменения логики обнаружения. |
| Положительный тест | Тестовый случай, для которого заранее ожидается выполнение условия детектора. |
| Отрицательный тест | Тестовый случай, для которого заранее ожидается отсутствие выполнения конкретного условия детектора. |
| Вариантный тест | Изменённое представление или вариант интересующего поведения, используемый для проверки устойчивости логики обнаружения. |
| `fast_pattern` | Механизм Suricata для предварительного отбора кандидатов по содержимому; конкретная семантика рассматривается при изучении правил. |
