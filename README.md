## GitHub Desktop workflow

> **Важно при обновлении существующего репозитория:** распаковка нового ZIP поверх старой рабочей копии заменяет существующие файлы, но **не удаляет** файлы, которые были исключены из нового релиза. Для v2.28 это критично: старые главы, Pre-Lab и bundles не должны оставаться под `docs/`.

1. Распаковать release candidate в отдельную папку и перенести изменения в репозиторий **или** после копирования поверх старой рабочей копии выполнить:
   ```bash
   python tools/migrate_v228.py
   python tools/migrate_v228.py --apply
   ```
2. После появления `.gitattributes` один раз нормализовать уже отслеживаемые текстовые файлы:
   ```bash
   git add --renormalize .
   ```
3. Проверить `git status`: старые student-facing файлы и устаревшие bundles должны отображаться как удаления, а не оставаться в рабочем дереве.
4. Выполнить:
   ```bash
   python tools/check_source_consistency.py
   ```
5. Проверить **Changes** в GitHub Desktop.
6. Commit to `main`.
7. **Push origin**.
8. Дождаться зелёного `Deploy GitHub Pages`.

Если workflow сообщает о `student-facing Markdown not listed in nav`, `legacy/internal material is published under docs/` и одновременно перечисляет старые bundles, это почти всегда означает **overlay-update**: новая версия была скопирована поверх старой без удаления устаревших файлов. Сам consistency checker в таком случае работает правильно.
