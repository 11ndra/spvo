## rc8.8 candidate


Этот candidate продолжает rc8.7 и закрывает отдельный quality gate по **90 официальным вопросам устного экзамена**. Лабораторные работы и их runtime-логика не изменялись.

Что изменено в rc8.8:

- все 90 вопросов повторно сопоставлены с основной теорией, а не только с `exam-prep.md`;
- уточнена модель уровней реакции IPS для вопроса 46;
- исправлена методическая неточность в вопросе 53: PCI DSS, NIST SP 800-53/SP 800-94 и ISO/IEC 27001 теперь разведены по типу документа и степени прямоты требований к IDS/IPS;
- уточнены примеры открытых IDS/IPS для вопроса 72;
- добавлена цельная последовательность внедрения IDS/IPS для вопроса 87;
- в `resources/sources.md` добавлены точные опоры на PCI DSS v4.0.1 Requirement 11.5.1 и NIST SP 800-53 SI-4.

### Наследованные изменения rc8.7

Этот candidate продолжает rc8.6 без изменения уже проверенных лабораторных работ. Основной scope релиза — содержательная доводка теоретического блока, соответствующего темам 9–15 рабочей программы SOPV 4311, и устранение регрессии визуального слоя.

Что изменено:

- темы 1–8 не переписывались и считаются ранее пройденным фундаментом;
- в Главе 9 усилены OSI, базовая безопасность распространённых сетевых протоколов, FTP/SFTP, SMTP/TLS, MitM, DDoS и связь защитных свойств с наблюдаемостью IDPS;
- модуль прикладной/веб-безопасности дополнен защитой данных в покое, управлением ключами и сессиями, secure defaults, автоматизированным сканированием, incident-management, обучением команды и правовым/стандартным контекстом из syllabus;
- endpoint-модуль дополнен тенденциями развития антивирусной защиты, ML/облачной аналитикой и ограничениями этих механизмов;
- профессиональный модуль дополнен математической базой, примерами языков программирования, социальной инженерией, автоматизацией/ИИ и практико-ориентированным циклом обучения;
- восстановлен pinned Mermaid 11.17.2 runtime + `mermaid-init.js` и CI source gate, которые присутствовали в rc5-WIP, но были потеряны в более поздней линии;
- добавлена responsive remediation для широких схем и семантические цветовые варианты process/gate-компонентов.

`mkdocs build --strict` и post-build link check остаются GitHub Actions gate, если локальная среда не содержит MkDocs.
